### Issue #48: Remove CAMI_WORKSPACE_PATH environment variable

**Labels**: `enhancement`, `priority:medium`
**State**: Open

#### Description

`$CAMI_WORKSPACE_PATH` is an artifact from when CAMI was an MCP server. For a skills-only plugin, environment variables are unnecessary complexity.

#### Current State

Multiple skill files reference this pattern:
```bash
# Check for custom workspace path
echo $CAMI_WORKSPACE_PATH
```

- If set: use that path
- If empty: use default `~/cami-workspace`

#### Proposed Change

1. Remove all `$CAMI_WORKSPACE_PATH` references from skills
2. Use `~/cami-workspace` as the only default
3. If custom path needed in future, store in `~/.config/cami/settings.yaml`

#### Files to Update

- `skills/cami/SKILL.md`
- `skills/manage-capabilities/SKILL.md`
- `skills/manage-sources/SKILL.md`
- `skills/create-project/SKILL.md`
- `reference/config-schema.md`
- `README.md` (remove custom workspace section)

#### Acceptance Criteria

- [ ] No references to `CAMI_WORKSPACE_PATH` in any skill files
- [ ] `~/cami-workspace` is the documented default
- [ ] README simplified (remove env var section)

### Issue #44: Add glossary and define terminology for novices

**Labels**: `documentation`, `priority:medium`
**State**: Open

#### Description

Terms like "agents", "skills", "sources", "roster", "workspace", "deploy" are used without definition. Users unfamiliar with Claude Code or CAMI will be confused.

**Examples of undefined jargon:**
- "Your current roster includes..." (what's a roster?)
- "Adding them to your lineup" (sports metaphor without context)
- "Sources are repositories of agents" (what are agents?)

#### Proposed Solution

1. Add "Concepts" or "Glossary" section to README.md and QUICKSTART.md
2. On first use, define terms inline: "agents (AI specialists with specific expertise)"
3. Consider a `/cami help terms` command

#### Acceptance Criteria

- [ ] All key terms defined in QUICKSTART.md
- [ ] README has glossary section
- [ ] New user understands terminology within 1 minute

### Issue #45: Improve QUICKSTART.md with "What is CAMI?" intro

**Labels**: `documentation`, `priority:medium`
**State**: Open

#### Description

QUICKSTART.md jumps into technical operations without explaining:
- What CAMI is and why you'd use it
- What a "workspace" is conceptually
- Why you'd want to "add sources"

#### Impact

Users who don't already understand the system have no anchor point.

#### Proposed Solution

Add 2-3 sentence intro explaining value proposition. First line should be:

> "CAMI helps you create and manage AI specialists (called agents) that assist with specific tasks in your coding projects."

Start with simplest possible action: "Create your first AI agent"

#### Acceptance Criteria

- [ ] First paragraph explains CAMI in plain English
- [ ] User understands value prop before diving into commands

### Issue #43: Add first-run onboarding experience

**Labels**: `enhancement`, `priority:medium`
**State**: Open

#### Description

No first-run detection or setup wizard exists. Skills assume users understand concepts like "sources", "workspace", "roster" without introduction.

#### Impact

Novice users bounce immediately due to cognitive overload.

#### Proposed Solution

Add first-run detection that checks if workspace AND config.yaml exist. If neither:

```
"Welcome to CAMI! Let me help you set up."
"CAMI helps you manage AI specialists (agents) for your projects."
"Want me to create your workspace and first agent?"
```

#### Implementation

1. First-run detection in `skills/cami/SKILL.md`
2. Welcome flow with inline concept explanations
3. Guided first agent creation
4. Hand off to normal flow after setup complete

#### Acceptance Criteria

- [ ] First-time users see welcome message
- [ ] Basic concepts explained inline on first run
- [ ] User can get to a working state in < 2 minutes
