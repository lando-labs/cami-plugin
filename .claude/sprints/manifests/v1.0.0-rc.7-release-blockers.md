### Issue #40: Remove references to non-existent guild repositories

**Labels**: `bug`, `priority:high`
**State**: Open

#### Description

The official registry references three GitHub repositories that don't exist:
- `github.com/lando-labs/fullstack-guild`
- `github.com/lando-labs/content-guild`
- `github.com/lando-labs/game-dev-guild`

**Location:** `reference/sources/official-registry.md`

#### Impact

Users will immediately hit "repository not found" errors when trying to follow documentation. This is the most damaging first-run experience possible.

#### Options

1. **Create and publish these repos** as public before launch
2. **Remove all references** and start users with "create custom agent" path only
3. **Mark as "coming soon"** or "example only" with clear disclaimer

#### Acceptance Criteria

- [ ] No references to non-existent repos in any documentation
- [ ] OR repos exist and are public
- [ ] First-time user can complete onboarding without errors

### Issue #41: Add LICENSE and CONTRIBUTING.md files

**Labels**: `documentation`, `priority:high`
**State**: Open

#### Description

No LICENSE or CONTRIBUTING.md file exists. This is a legal and community blocker for open-source.

#### Impact

- Users cannot legally use, modify, or distribute without a license
- Contributors don't know how to contribute
- Organizations may reject adoption due to legal uncertainty

#### Recommendation

1. Add LICENSE file (MIT or Apache 2.0 recommended)
2. Add CONTRIBUTING.md with:
   - Bug report guidelines
   - Feature request process
   - Pull request process
   - Code style expectations

#### Acceptance Criteria

- [ ] LICENSE file exists with appropriate open-source license
- [ ] CONTRIBUTING.md exists with contribution guidelines

### Issue #42: Replace hardcoded /Users/lando/ paths in documentation

**Labels**: `bug`, `priority:high`
**State**: Open

#### Description

Documentation examples contain hardcoded `/Users/lando/cami-workspace/` paths.

**Locations found:**
- `reference/config-schema.md` (lines 115, 122, 434, 467, etc.)
- `skills/manage-capabilities/SKILL.md`
- `skills/create-project/SKILL.md`

#### Impact

Author-specific paths confuse users and make examples non-portable.

#### Fix

Replace all `/Users/lando/` paths with:
- `~/` or `$HOME/`
- OR `<username>` placeholder: `/Users/<username>/cami-workspace/`
- Add note that paths are examples and will differ per user

#### Acceptance Criteria

- [ ] `grep -r "/Users/lando" .` returns no results
- [ ] All example paths use portable notation
